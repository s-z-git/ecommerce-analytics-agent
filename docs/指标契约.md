## 0. 五个已定稿口径

| 口径 | 最终决定 | 实测参考 |
|---|---|---|
| GMV 是否含运费 | **不含** | 含运费会增加约 16.64% |
| 取消率 | **分子只算 canceled；分母全部订单** | canceled 0.63%；canceled+unavailable 1.24% |
| 延迟率 | **分母 = 已送达订单**（`order_status='delivered'` 且送达时间非空） | 8.11% |
| 复购率 | **按 `customer_unique_id` 去重** | 有有效订单客户 2,888/94,990=3.04%（全客户 2,997/96,096=3.12%） |
| 支付占比 | **按支付金额**（不是笔数） | 信用卡 78.47%、boleto 17.96% |

## 1. 12 个指标

| id | 指标 | grain | shape | 口径 | 允许维度 |
|---|---|---|---|---|---|
| `gmv` | 商品交易总额 | order | grouped | `SUM(order_items.price)`，不含运费，排除 canceled/unavailable | month, state |
| `orders` | 订单数 | order | grouped | `COUNT(DISTINCT order_id)`，与 GMV 同一过滤集合 | month, state |
| `aov` | 客单价 | order | grouped | GMV / 订单数，分子分母同一集合 | month, state |
| `cancel_rate` | 取消率 | order | grouped | canceled / 全部订单 | month, state |
| `delay_rate` | 延迟送达率 | order | grouped | 实际送达晚于预计送达 / 已送达订单 | month, state |
| `delivery_days` | 平均配送天数 | order | grouped | 下单到签收的自然日差，仅已送达 | month, state |
| `repeat_rate` | 复购率 | customer | grouped | 有效订单≥2 次的 `customer_unique_id` / 至少有一笔有效订单的客户 | 无（也不允许过滤） |
| `avg_rating` | 平均评分 | order | grouped | 先按订单取评价均值，再求平均 | month, state |
| `category_revenue` | 品类收入 TopN | order_item | topn | `SUM(price)`，品类 null 归“未分类” | 固定维度：品类 |
| `seller_revenue` | 卖家收入 TopN | order_item | topn | `SUM(price)`，按 seller_id 分组 | 固定维度：卖家 |
| `payment_share` | 支付方式占比 | order | topn | `SUM(payment_value)` 占比，排除 canceled/unavailable | 固定维度：支付方式 |
| `gmv_mom` | GMV 环比 | month | series | 月度 GMV + `LAG`；date spine 补缺月，缺月/残月返回 NULL | 无（也不允许过滤） |

> 允许过滤是独立字段：所有可过滤指标都只允许 `state`；时间统一用 `time_range`，不要用 `month` 过滤；`repeat_rate` 和 `gmv_mom` 不允许过滤。

## 2. 防重复计数

`order_items`、`order_payments`、`order_reviews` 都是一对多。当前契约的做法：

- `items_agg`：先按 `order_id` 聚合商品金额
- `pay_agg`：先按 `order_id` 聚合支付金额
- `review_agg`：先按 `order_id` 聚合评价均值
- `pay_types`：按 `order_id + payment_type` 聚合
- `cust_orders`：按 `customer_unique_id` 统计订单数

**规则：子表先聚合到目标 grain，再 join。** 不要直接三表 join。

实测参考：112,650 条商品行直接 join 支付/评价后变成 117,329 行；全量 GMV 净影响约 +4.0%，局部订单最多 29 条支付、3 条评价。

## 3. 时间锚点

- 数据购买时间：`2016-09-04 21:15:19` ~ `2018-10-17 17:30:18`
- `as_of_sql`：`SELECT MAX(order_purchase_timestamp) FROM orders`
- 不用 `today()`；用户说“最近/本月”时按数据截止日往前推
- 月趋势只用完整月份：建议 `2017-01` ~ `2018-08`；2016-09/10/12 和 2018-09/10 都太少

## 4. 验收集（acceptance set）

- 文件：`eval/questions.holdout.jsonl`（acceptance set；文件名是早期命名，不是 blind holdout）
- 当前 12 条，一条覆盖一个指标；11 条 `expect=answer`，h05（2018 全年）为 `expect=clarify`——数据只到 10-17，按设计应澄清而不是硬算

- 12 条 gold SQL 已与编译器结果逐条比对：**12/12 行集一致**（series 题按顺序比较）
