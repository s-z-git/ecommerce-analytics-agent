# 3 分钟演示脚本

> 目标：3 分钟内让人相信三件事——① 数字是算出来的，不是模型编的；② 模型没有写 SQL 的自由；③ 全链路可评测。
> 演示前：优先本地 `uvicorn` + `streamlit`，确认 http://127.0.0.1:8501 能打开；Docker 只作为可选封装。

## 0:00–0:25 提出问题

口播：

> 这是一个人项目的受约束 NL2SQL 应用（产品名叫电商经营分析 Agent）。用户用中文问经营问题，系统返回数字和口径。
> 关键区别：大模型不写 SQL，只输出结构化的 QueryPlan；SQL 由 12 条指标契约渲染，
> 在 DuckDB 上只读执行。所以同一问题永远得到同一个口径，模型没法"自由发挥"。

## 0:25–0:50 数据与契约

口播：

> 数据是 Olist 公开数据集，6 张表 547,593 行，截止 2018-10-17。
> 我定了 12 条指标口径，比如 GMV 不含运费、取消率分母是全部订单、复购率按
> customer_unique_id 去重。口径写在 YAML 里，改口径不用改代码。

## 0:50–1:50 现场提问（UI）

依次输入（每条约 3–5 秒）：

1. `2018 年 1 月的 GMV 是多少` → 945,456.29
2. `2018 年上半年各州订单数` → 27 行，SP 第一
3. `销售额是多少` → 弹出澄清："指 GMV 还是支付金额？"

口播（第 3 条之后）：

> 这就是设计的"不猜"：口径有歧义时先问，而不是自己选一个。

## 1:50–2:25 安全与可解释性

1. 输入 `帮我删掉所有订单` → 返回"不支持删除/修改"。
2. 展开"看生成的 SQL"：

口播：

> 模型能影响的只有 JSON 里的字段：选哪个指标、哪些维度、什么时间范围。
> SQL 从这里出来，经过 sqlglot 白名单校验，最后走只读连接。
> 所以我不说"防注入"，我说的是攻击面被消掉了。

## 2:25–3:00 评测数字（收尾）

口播：

> 评测不是比 SQL 字符串，是比执行结果：
> 12 条 acceptance set 12/12，30 条功能题 3 轮 90/90（22 answer + 3 clarify + 5 unsupported，0 翻转），
> 单测 125 条覆盖契约校验 / SQL 编译 / guard 拦截 / HTTP 状态码映射四层，12 个指标全部编译并真实执行通过。
> 工程化封装另有 MCP Server（不暴露 execute_sql），不是主卖点。

（如时间富余：展示工程化封装 `src/mcp_server.py` 或 `docker compose ps`，但不作为主叙事。）

## 常见追问

| 追问 | 回答 |
|---|---|
| 为什么不让模型直接写 SQL？ | SQL 是不可枚举的输入空间，没法做白名单；QueryPlan 字段有限，可以逐字段校验。 |
| 怎么防重复计数？ | 一对多子表先聚合到订单粒度（items_agg / pay_agg / review_agg），再 join 订单。 |
| "最近一个月"怎么算？ | 锚定 max(order_purchase_timestamp)，不用 today()。 |
| 模型输出不合法怎么办？ | 校验错修 1 次；编译/执行错不重试，直接返回错误码；空结果/全 NULL 返回 no_data。 |
| 为什么不用 LangGraph？ | 五步固定流程 + 三个分支，手写状态机每个分支都能在 trace 里看到。 |
| 这套东西的边界？ | 单指标、只有 month/state 两个维度、不支持预测/归因、无多轮追问；`gmv_mom` 是硬编码 SQL；数据截止 2018-10-17。边界写进了 prompt、README 和评测。 |

## 演示前检查

- 演示前先跑一遍 4 个问题，确认 API key 有效、Docker 已起。
- 不要现场调 prompt，也不要打开 `eval/questions.holdout.jsonl`（acceptance set，文件名为早期命名，不是 blind holdout）。
- 报数字用本文档里的数字，不要说"大概""应该"。
