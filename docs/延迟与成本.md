## 6. token 与成本

30 题功能集的平均 usage：

| 字段 | 平均值 |
|---|---:|
| prompt_tokens | 1622.2 |
| completion_tokens | 219.9 |
| total_tokens | 1842.0 |

估算单次成本时使用供应商当期单价：

```text
单次成本 = 1622.2 / 1_000_000 * 输入单价 + 219.9 / 1_000_000 * 输出单价
```

本仓库未配置模型单价，因此**不写具体金额**，避免把未核实的报价当成事实。若已知当前供应商单价，可直接传入脚本估算（金额单位取决于传入单价）：

```powershell
F:\CondaData\envs\commerce\python.exe scripts\trace_stats.py `
  --since 2026-11-08T18:46:58 --until 2026-11-08T18:48:01 `
  --input-price-per-1m <输入单价> --output-price-per-1m <输出单价>
```

## 9. 已知边界

- 全量 trace 含开发调试流量和 P2 注入探针，不代表生产 SLA。
- 旧 trace 没有 `usage` / `llm_ms` / `sql_ms`，只有新增记录才有；token 和阶段统计只基于 30 题功能集。
- 30 题功能集是固定题集，不是随机抽样；它适合做回归对照，不适合外推所有问题的延迟。
- `malformed` 是**全文件计数**，不随 `--since/--until` 过滤后重算；这是为了不隐藏文件里的坏行。
- `--since/--until` 支持带时区 ISO 输入；脚本会去掉 tzinfo，按 trace 的本地 naive 时间比较。
- P95 会随模型服务波动；报告保留统计日期和命令，便于之后复算。
